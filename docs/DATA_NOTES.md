# WANDS data notes

Generated by `wands data profile` at commit `unknown` from WANDS commit `3b74dcf`. Do not edit by hand.

## Files

All three files are UTF-8 and tab-separated, as `read_dataset.ipynb` shows. Three traps:

- `query.csv` is CSV-quoted: three queries hold an escaped inch mark (`writing desk 48"`). Reading it with quoting off leaves literal `"""` in the query text.
- `product.csv` has raw inch marks inside fields, so it is read with quoting off.
- The header says `category hierarchy` with a space, though the README says `category_hierarchy`. `data.load` renames it.

Checksums: SHA-256 is pinned in `wands/data.py`. On first download each file's git blob id was also compared with the blob ids GitHub lists for that commit, and all three matched.

Rows: 42,994 products, 480 queries, 233,448 labels. Query ids are not contiguous (max 487).

Empty text fields: `product_name` 0, `product_class` 2,852, `category_hierarchy` 1,556, `product_description` 6,008, `product_features` 0.

## Labels

Overall: Exact 25,614, Partial 146,633, Irrelevant 61,201.

| per query | min / median / max |

| Exact | 0 / 10 / 878 |

- **Duplicates.** 1,467 (query, product) pairs are labelled more than once, in 121 queries, leaving 231,873 unique pairs. 14 of them disagree. `build_qrels` keeps the highest gain; with so few conflicts the rule can't move a mean by much.
- **No Exact label.** 101 queries have none, so Exact-only NDCG and MRR are undefined there. Those metrics skip such queries instead of scoring them 0, and each report gives the number of queries scored.
- **Nothing relevant.** 1 query has no Exact or Partial label, so graded NDCG skips it too.
- **Recall@100 can't reach 1.** The median query has 170 relevant products and the largest has 3,495, so 100 results can't hold them all. Reports add `capped_recall@100` (divide by min(relevant, 100)), which is the honest ceiling for a reranker.
- **Pool depth.** 8 products have no label at all, but a product labelled for one query is usually unlabelled for another. `judged@10` shows how much that matters.

Most of the top keys are compliance or logistics fields, and a shopper's query never mentions them. So query understanding's vocabulary is the shopper-facing groups in `wands/qu/attrs.py` (color, material, style, shape, pattern, room, size, theme), each of which pools several keys, such as `basecolor` and `topcolor`.

Keys are not searchable text: `mirror : no` must not match the query "mirror". `feature_text` keeps values only, and drops yes/no flags and bare numbers.
